## b · Conflicts and the changes
1. **Scope: packs whose return is read from the ledgers (`returns.id`: AU, AE), not IN.** The critic's B4 "one rule, both countries" would refuse every IN year close until twelve gstclose entries exist — a money rule DECISIONS (30 Oct, Q2) does not say ("any BAS period") and books-year.test proves today's IN behaviour. The helper is country-neutral (it reads the pack's table and the closes' own records); the gate's reach is the pack's `returns.id`. IN joins with one condition when Athi says so (auditor list).
2. **Month lock stays allowed, every month** (DECISIONS Q2, the coordinator's brief) — the critic's "refuse the period-end month" needs Athi's yes (its own words) and is not built; the lock advice carries `return: { form, period, label, closed }` so the screen says what is open.
3. **A close is recognised by the reason's PREFIX ('Tax period closed — '), never the label text** (critic B9, coordinator 30 Oct): one predicate `lockedByTaxClose` for closedBefore and the new state; a close stored under the old label still answers duplicate (tested). The AE stagger has no key yet, so an AE year's table cannot be built: the state says `needs: 'stagger'` and the gate does not refuse (never guessed; a settings item, handed to cb-settings).
