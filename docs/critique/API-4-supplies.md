# Critique · API-4 sweep: supplies (5 routes of routes/supplies.js, /api/supplies) · stage 2 · written before the first route edit

(a) The brief assumes, checked against the code
- 5 routes, mounted at /api/supplies (server.js:479): TRUE. GET / :32, POST / :53, PATCH /:id :77, POST /purchase :97, POST /:id/issue :116 (base lines). Main's register: GET / and POST /purchase "partial", the other three "not started".
- Four catch-and-refuse shapes, all in the handlers: `fail()` -> 500 `{ error: <screen label>, message: <the generic sentence> }` (safeErr: the real error is logged, the caller gets the fixed sentence); 400 `{ error: 'validation', message }`; 404 `{ error: 'Not found' }` (PATCH only); 503 `{ error: 'Not ready', message: 'run b217 first' }` (a missing table, POST / and POST /purchase only). GET / answers a missing table as a 200 `{ supplies: [], not_ready }`; PATCH and issue answer it as a 500.
- Every text that reaches an answer, traced to its source:
  - `made.error` (POST /): lib/supply-store.js:87 and :124 'a supply needs a name', :106 and :159 'the supply could not be created'. FIXED words.
  - `out.error` (POST /purchase): lib/supply-store.js:207 'a purchase needs at least one line', :211 'a purchase needs its own reference ...'. FIXED words.
  - `r.error` (issue): lib/supply-store.js:304 'no such supply', :305 'this supply is expensed when it arrives ...'. FIXED words.
  - `r.why` (issue, :123) and `failed[].why` (the 200 body of POST /purchase): lib/supply-store.js 'a purchase of nothing records nothing', 'a supply needs a name' (fixed), and stock-store.post -> lib/inventory.js check()/apply(): FIXED sentences, EXCEPT lib/inventory.js:189 'this stock is counted in <stored unit>, and the movement is in <unit sent>': the unit is TEXT THE CALLER SENT (or the one stored from an earlier call). Also :105 'no such reason: <reason>' (the reason is fixed by supply-store: 'purchase', 'issued'; unreachable from these routes).
  - FINDING for cb-security (not fixed): the unit of a stock line is echoed back in a 400 message (base routes/supplies.js:123, now :125) and in a 200 `failed[].why` (lib/supply-store.js:280 r.why -> out.failed, answered by routes/supplies.js:111 in the base, now :110). Own text echoed to its own shop, no exception or database text, but it is caller text in a 200, so POST /purchase and POST /:id/issue are never 13 of 13.
- No answer carries exception or database text: the 500s are the fixed sentence; a scene makes the database throw a string with SQL in it and the scan covers 2xx, 4xx and 5xx bodies.
- Money: POST /purchase IS a money write in the register's sense (docs/contracts/api-hardening-scope.json lists it). It needs an Idempotency-Key = a new required input = a behaviour change: LISTED for cb-operations and cb-api, not added. Today a resend is already safe for a counted line (lib/stock-store.js post() is idempotent on entity, ref, line_ref, reason) and re-stamps last_cost for an expensed one; the answer is the same. POST /:id/issue is NOT in the money list (a stock movement, no money field); its resend with no `ref` is a NEW movement (ref 'use-' + Date.now()): an owner question.
- Ids handed to an INSERT or UPDATE (the finance pass's foreign-key lesson): none comes from a body. PATCH /:id: UPDATE ... WHERE entity_id = $1 AND supply_item_id = $2. Issue: the supply is SELECTed under the shop first, and the stock movement is posted with that row's id. Purchase: a line is found or made BY NAME under the shop (ensureMany); a `supply_item_id` in a line is never read (a scene proves no statement receives it). stock_balance / stock_movement carry no foreign key to supply_item (polymorphic item_id + item_kind), so nothing checks "a row exists under any owner". No P1; a T2 case per id route still confirms it on real Postgres.

(b) Conflicts with rules
- NO BEHAVIOUR CHANGE. The schemas say what the handlers ALREADY take: a body is an object or a list (a list was read as an empty body and answered the library's own 400), nothing is required, a value is anything (a number for `name` is read as its text; a non-true `keep_stock` is false), a query value is anything (`?all=1&all=1` is not '1' and lists the live ones). So the schema in front of each route refuses nothing; strict_input stays open on the three writes (an unknown key is dropped today; refusing it is a new 400 and an owner's decision, listed).
- A malformed id is a 500 on real Postgres (a uuid column compared with "nope" raises 22P02 and falls to the generic 500): the stand-in answers 404 for it. Left as is (a 400/404 would be new), listed for API-4c.
- Issue answers an unknown id AND another shop's id 400 'no such supply' (the lookup is under the shop, so they are identical): not a leak, but not the 404 the 9th world wants. It stays failing on foreign_id_404 (and partial on error_tests for 404) and is listed, grouped by answer, for API-4c.
- POST /purchase answers 200 'Purchase recorded' even when every line failed (failed[] holds the reasons): an owner question, left.
- HELD_FILES: not added (no route reaches 13 of 13; the unit echo keeps the two writes out, and output_allowlist / trips_budgeted are listed, never closed by hand).
- The relay (`message: r.why`, the 400 `message: <library sentence>`) moves into lib/supplies-contract.js: the raw-error ratchet stops counting it. It still relays fixed words, plus the unit echo above. The PR says so.

(c) Simpler way: none. The sweep is the kit as it is (lib/contract-kit.js `list`, `lenient`, `inline`; lib/products-contract.js `said`, `failed`; tests/lib/problem-world.cjs; tests/lib/foreign-id-world.cjs). Nothing is forked and the kit is not widened. `declaresStatuses` (privacy #388) is not on main: if the register needs a 503 the handler cannot spell, the status is spelled in the handler.

(d) Risks: each refusal gains the Problem fields beside every old key (added, registered with real sentences); the 500 gains `code: 'INTERNAL'`. The web reads these routes (public/app: supplies screen) by `error`/`message`/`says`, all kept. Other sweeps edit scripts/guards.cjs, engine-manifest and generated files (merged from origin/main).

(e) VERDICT: BUILD WITH CHANGES (the relay moves into the contract and still relays fixed words plus the unit echo; strict_input, output_allowlist, trips_budgeted, idempotent_money_write and the issue's foreign_id_404 are listed, not closed). No route is signed; human{} stays null.
