# Critique · API-4 sweep: kyb (5 routes of routes/kyb.js, /api/kyb) · stage 2 · written before the first route edit

(a) The brief assumes, checked against the code
- 5 routes, mounted at /api/kyb (server.js:457): TRUE. GET /yourself :12, POST /credential :20, GET /position :30, GET /risk :38, POST /field :46. Main's register shows all five "not started", seven columns all no.
- POST /credential relays `err.message` for any status under 500 (routes/kyb.js:26): TRUE. Every throw that can reach it carries FIXED words: lib/kyb.js:113 "a title or standard_key is required" (400), and lib/readiness.js:407 "standard_key and doc_key required" (400, which cannot be reached from here: lib/kyb.js:104-111 always makes both). A database error carries no `.status` (a pg error has a SQLSTATE `code`, db/index.js sets none), so no database or caller text rides the relay. NOT a finding for cb-security. The relay still relays: if it moves into a spec the raw-error ratchet stops counting it, and the PR says so.
- The other four answer `err.status || 500` with safeErr (routes/kyb.js:16,34,42,50): TRUE. No library call under them throws a status that reaches the route (every read inside lib/kyb.js is caught: :42, :50-59, :125-127, :196-210, :263, :326, :330-340). The only statuses in the libraries it calls (lib/profile.js:165 409, :228 503) are save-side and unreachable. So today these four can answer only 500; the pass-through of a status is kept (frozen), declared only as 500.
- A 500 is reachable only by a throw outside those catches: a bad KYB_STRUCTURAL / KYB_* setting (lib/kyb.js:14-36, `JSON.parse`), the write inside POST /credential (lib/readiness.js:427, a bad `valid_until` or a failing database), and the response write itself. The database failing on a READ answers 200 with empty facts (silent by design: log.fellBack). That is a finding for the owner, not changed (frozen).
- No 200 carries exception text: TRUE (grep of lib/kyb.js and the readiness/profile paths it reads: `e.message` only reaches the log; `why` in lanes is readiness.js:270 fixed words ORIGIN_UNSTATED / SECTOR_UNSTATED).
- All five are entity-scoped from the token (`auth.entityOf(req)`), no id in the path: TRUE. So no foreign-id (S35) scene applies by path. POST /credential's body names `evidence_ref` (a chit id): its world is run on it (lib/readiness.js:419-426 nulls a ref that is not an owned chit, so a foreign chit id and an unknown one answer the same 200 and write the same row). GET /position's query names `vertical` and `origin` (a sector key and a country), never an entity: no world.

(b) Conflicts with rules
- FROZEN BY VALUE (Athi 23 Oct): lib/kyb.js, SQL, the metering and 24h cache, the `declared / documented` states and the "makes NO governance claim" notes are not touched; the notes are replayed byte for byte.
- POST /field is a metered write (lib/kyb.js:382-388 inserts a usage_ledger row, cost KYB_FIELD_COST_USD, and a cache row; the 24h cache on entity + profile hash is its only idempotency). It is not in docs/contracts/api-hardening-scope.json money_writes; requiring an Idempotency-Key there is a new 422, so it is LEFT to cb-api and the owner. Today the provider is inert (lib/kyb.js:313-318 returns null) so it charges nothing and writes nothing.
- Findings (not fixed): lib/kyb.js:337 spreads the cached result AFTER `cached: true, charged: false`, so a hit would answer `cached:false, charged:true` (unreachable today, the cache is never written); an unparsable `valid_until` is a 500, not a 400 (readiness.js:427).
- A body that is a list, or a repeated query key, is NOT refused (declared `object or array` and `lenient`): no new 400, so nothing to grep in the web (the web sends `{title}` / nothing: public/know-your-business.html:223,231,376).
