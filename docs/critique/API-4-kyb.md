# Critique · API-4 sweep: kyb (5 routes of routes/kyb.js, /api/kyb) · stage 2 · written before the first route edit, closed with the measured result

(a) The brief assumes, checked against the code
- 5 routes, mounted at /api/kyb (server.js:457): TRUE. GET /yourself :12, POST /credential :20, GET /position :30, GET /risk :38, POST /field :46 (base lines). Main's register showed all five "not started", every column no.
- POST /credential relays `err.message` for any status under 500 (base routes/kyb.js:26): TRUE. Every throw that can reach it carries FIXED words: lib/kyb.js:113 "a title or standard_key is required" (400) and lib/readiness.js:407 "standard_key and doc_key required" (400, unreachable: lib/kyb.js:104-111 always makes both). A database error carries no `.status` (a pg error has a SQLSTATE `code`; db/index.js sets none), so no database, exception or caller text rides the relay. NOT a finding for cb-security. The relay still relays: moved into lib/kyb-contract.js (credentialFault) the raw-error ratchet stops counting it (33 → 32); the signer reads the spec, not the count.
- The other four answer `err.status || 500` with safeErr (base :16, :34, :42, :50): TRUE. No library call under them throws a status that reaches the route: every read in lib/kyb.js is caught (:42, :50-59, :125-127, :196-210, :263, :326, :330-340, :359-363, :382-395); lib/profile.js:165 (409) and :228 (503) are save-side. So these four answer only 500 today; the pass-through of a carried status is kept (frozen, replayed with an injected 409/503/502) and declared as 500 alone. The generic sentence is the only message, whatever the status.
- A 500 is reachable only by a throw outside those catches: a bad KYB_* setting (lib/kyb.js:14-36 `JSON.parse`), the write inside POST /credential (lib/readiness.js:427: a bad `valid_until`, a failing database) and the answer that cannot be written. A database that fails on a READ answers 200 with empty facts (log.fellBack): silent by design, an owner question, not changed.
- No 200 carries exception text: TRUE (grep of lib/kyb.js and the readiness/profile paths it reads: `e.message` reaches the log only; `why` in lanes is readiness.js:270, fixed words). The test scans 2xx, 4xx and 5xx bodies of 58 answers with a database that throws SQL text and a library that does.
- All five are entity-scoped from the token (`auth.entityOf`), no id in any path: TRUE, so S35 (foreign id) has no 404 to prove. The one id a body names is POST /credential's `evidence_ref` (a chit): row security hides another shop's chit, readiness.js:419-426 drops a reference that is not an owned chit, so a foreign chit and an unknown one answer the same 200 and write the same row (run as the 9th world on the body, pass). GET /position's query names a sector and a country, never an entity.
