# Critique · API-4 sweep: the bell (6 routes: routes/events.js /api/events and routes/notifications.js /api/notifications) · stage 2 · written before the first route edit

(a) The brief assumes, checked against the code
- 6 routes, 2 routers: events.js POST /ticket :15, GET /stream :20, GET /stats :33; notifications.js GET / :48, POST /seen :175, POST /dismiss :204 (base lines). Main's register: all six "not started" (a hardening column that does not apply passes for free; none of the seven core columns does).
- Money: none. docs/contracts/api-hardening-scope.json lists none of the six in money_writes (the dismiss and seen words are not money words). The 9th world: no route has an id in its path, so foreign_id_404 does not apply to any of the six. The id surface is the body of POST /dismiss (`log_ids`), checked below.
- Four refusal shapes, all in the handlers: 401 `{ error: 'Unauthorised' }` (POST /ticket when the login names no entity), 401 `{ error: 'Unauthorised', message: 'ticket missing, spent or expired' }` (GET /stream, signed out by design), 400 `{ error: 'Nothing to clear', message: 'Send log_ids, or all:true.' }`, 503 `{ error: 'Not migrated', message }` (seen, b157) and 503 `{ error: 'Not migrated', message, code: 'NOTIF_DISMISS_NOT_MIGRATED' }` (dismiss, b164), and the three 500s `{ error: <label>, message: safeErr(err) }`. GET /stats is refused by lib/platformroot refuseUnlessRoot (already a Problem since #372: 404 NO_PLATFORM_ROOT, 403 NOT_PLATFORM_ROOT).
- Every text that reaches an answer, traced to its source:
  - `safeErr(err)` (lib/respond.js:13): logs the real error and returns the one constant SAFE_SENTENCE ('Something went wrong — please try again.'). It can pass NOTHING of the error. The three 500 messages are that constant.
  - `message` of the two 503s and the 400, and the stream's 401 sentence: literals in the route file. No interpolation anywhere in either file.
  - 200 bodies: POST /ticket `{ ticket, ttl_s }` (lib/events.js ticketFor: 24 random bytes, 60), GET /stats three integers, POST /seen `{ ok, seen_at }` (the definer's timestamp), POST /dismiss `{ ok, cleared }` (a row count), GET / `{ notifications, count, total, page, limit, seen_at }` or, with `?count=1`, `{ count, total, seen_at }`. The feed rows are columns of state_log / chit_header read by the one SELECT (explicit column list); `detail` and `action_by_display_name` are STORED event text written by the rail's writers (30 INSERT INTO state_log sites: none writes an exception message into it, the only `.message` near them is a console.error). No exception text, no database text, no provider text reaches any answer, 2xx included.
- POST /ticket and GET /stats have no try/catch: a throw goes to server.js's error handler (fromError, a 500 INTERNAL with the old `{ error: 'Server error', message: 'Something went wrong' }`). That is already a Problem and stays.
- FOREIGN KEY (SEC-100, the P1 class): `notif_dismissed` has NO foreign key. migrations/000_baseline_2026-10-21.sql:4238 creates it with only a primary key (entity_id, log_id) (:6272) and the entity policy (:10015); migrations/archive/b164_notif_dismissed.sql says "NO FOREIGN KEY TO state_log, DELIBERATELY" (a RESTRICT would let a dismissal block a retention purge). So there is no existence oracle: a log_id of another shop, a log_id nobody has and a made-up uuid all insert under the CALLER's entity and answer `{ ok: true, cleared: 1 }`. Not a P1. What it does mean: `cleared` counts rows written, not events hidden, so junk uuids make orphan rows (harmless: nothing reads an orphan, but the table can be filled by a signed-in shop with any uuid, it is that shop's own rows under RLS). A string that is not a uuid is Postgres 22P02 inside `unnest($2::uuid[])` and answers the safe 500. Listed for API-4c (cb-connect): a 400 for a malformed log_id and a `cleared` that counts only visible events are new behaviour, not made here.
- A scene proves a body `entity_id` is never read (the INSERT takes the shop from the session).

(b) Conflicts with rules
- NO BEHAVIOUR CHANGE. The input schemas say what the handlers ALREADY take: every body is an object or a list (the handlers read a list as no body), nothing is required, a value is anything (`all` is true only when `=== true`, a `log_ids` that is not an array is read as none), a query value is anything (`?count=1&count=1` is not '1'; `?limit=abc` falls back to 30). The schema in front of each route refuses nothing, so:
  - strict_input stays open on POST /ticket, /seen and /dismiss: closing the body would turn an unknown key (dropped today) into a refusal (new). Listed.
  - error_tests stays failing on the five routes whose schema check declares a 422 (or 400 on /dismiss, where it is the same 400 the route answers itself, so /dismiss CAN pass) that nothing can answer: the register forces a POST to declare 400 or 422 and a route that declares a query to declare a refusal. Listed as "no refusal exists" (T-16).
- GET /stream's success is a stream. The kit declares it with media('text/event-stream'): schema_out passes (a string of its media type); output_allowlist fails (a stream has no JSON allow-list to close). Never closed by hand (laptop1 ruling); listed.
- The 401 of GET /stream is the one public refusal; the stream is opened ONLY with a one-time ticket in `?t=` or `?ticket=`; both spellings keep working (a scene opens the real stream with each, and a spent ticket is refused). Its framing (retry, hello, cb, ': ping' plus the named ping every 25 s) is not touched: lib/events.js is not edited, and a test reads the first frames from the real stream and the heartbeat from the real timer.
- POST /ticket's `if (!e) return 401` is a gate inside the handler: the 401 is already a status auth implies, and it is spelled as a literal in the handler so the register reads it.
- GET /stats' refusal is written by a helper the handler calls (refuseUnlessRoot): it becomes a gate with `addsStatuses: [403, 404]`, the way routes/entities.js rootGate does (a copy of that one-line gate; the owner may move it into lib/platformroot.js, which this sweep must not edit; listed under One source).
- HELD_FILES: not added unless every route in the file reaches 13 (none will: output_allowlist and trips_budgeted are listed).
- The `message: safeErr(err)` relays move into `faultOf` (lib/products-contract.js `failed`): the raw-error ratchet stops counting them; they relay only the constant sentence. The PR says so.

(c) Simpler way: none. Two routers, so two contractOf calls in ONE file (lib/bell-contract.js; the kit takes one mount per contract); one `words` table, one faultOf (`failed` of lib/products-contract.js, reused as supplies does). The harness gets one opt-in, `scenario.until` (read the first frames of a stream and close it), in tests/lib/problem-world.cjs; nothing is forked.

(d) Risks: each refusal gains the Problem fields beside every old key (added, registered with real sentences); the 500 gains `code: 'INTERNAL'`. The web reads these routes (public/app/rail-bell.js, core.js, till.html) by status and by the success keys; the stream is read by EventSource, which only needs a 200 and fails on anything else, as before. docs/contracts/web-api.json holds no entry for these routes. The stream test must never hold a socket open: every stream the tests open is destroyed after its first frames and the process exits.

(e) VERDICT: BUILD WITH CHANGES (relays move into faultOf and still relay only the constant sentence; strict_input, output_allowlist, trips_budgeted, and error_tests on the routes that can refuse nothing are listed, not closed). No route is signed; human{} stays null.
