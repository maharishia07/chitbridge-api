(a) The brief assumes, checked against the code
- 6 routes at /api/definitions (GET /, GET /:id, POST /, PUT /:id, DELETE /:id, POST /freeze; server.js mount; the register has 6 rows of routes/definitions.js, all "not started", 7 columns false): TRUE.
- Every refusal is a bare `res.status(N).json({ error, message })` and every 5xx goes through safeErr (routes/definitions.js:207,253,317,421,481,553): TRUE. No `e.message` is ever sent. Two chains of express-validator (POST / at :258, POST /freeze at :503) answer `{ error: 'Validation failed', details }` through validate(); for kind/name a missing or null value is listed TWICE per field (isString and notEmpty both fail), measured on the base.

NO exception text is reachable in any answer, 200 included (traced, see the PR).
- POST /freeze writes nothing and is not in the money list (hardening-scope money_writes on #337 holds 12 routes, none of these). POST /, PUT /:id and DELETE /:id write definition rows and an append-only definition_version row: they move no money, so idempotent_money_write does not apply; a repeat POST / answers 409 Name taken (unique index), a repeat DELETE is a no-op 200.

The offline world proves the handler; the real fence is the T2 case (tests/definitions-truth.realstack.cjs, written, not run here).
