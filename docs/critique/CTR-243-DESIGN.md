# CTR-243 design: a bill rung offline at an out-of-date price is confirmed before it is sent (CTR-212 S2b)
Status: DESIGN v2 (amended after cb-critic CHANGE, CTR-243-CRITIC.md), no code. Money: cb-critic before build and again on the branch. Owner: counter. 2026-11-13.
Consulted: cb-catalogue pack (CAT-264a stamp, PM/CTR-212 section 11), cb-accounting (rate move, via the CTR-212 plan), cb-api (answer shape). Read-only advice; the owner decides.

## 0. What exists (api origin/main c32056f2, till.html found by name)
- CTR-212 S1/S2a landed: POST /api/till/recheck (routes/till.js recheckAnswer; its `stamp` = item_data.price_changed_at, a HINT only per R2); till recheckBeforeBill, recheckBasis, `business_json.price_basis {checked, at, snapshot_at, parked_at, reason, kept[]}`; each line carries `catalogue_stamp`.
- A bill finished OFFLINE already says `price_basis.reason = 'offline'` (or `recheck_failed`) and joins the queue. Nothing asks anyone when it later reaches the server: drain() posts `bill.chitBody`.
- migrations/b845 added `catalogue_items.commercial_changed_at` (the one price/rate/status stamp, set by trigger), but the recheck door does not return it yet.
- Seams: `seams.cjs stale | catalogue_version | pageStale | tillStamp` found nothing reusable by those words (the stamp is `commercial_changed_at`; the version is `TILL_BUILD`). Reuse: recheckRead, recheckBasis, the CTR-212 diff popup (offersReread style), ownerPinAsk, the CTR-191 warn row, qDue/held, queueCount(), the till-park dbFrozen guards, TILL_BUILD.
- CTR-246 pattern to copy: the bill carries the till build (`till.build` / page), the later check decides by the stamp, an old build is counted not refused, pageStale forces reloads, a new build string is the switch. Here the till decides, so the build stamp only says whether a bill COULD have been checked.

## 1. How the till knows a price is stale (no second formula; carried values compared)
A queued bill is a candidate when ALL hold: it has `price_basis` and `price_basis.checked !== true` (reason offline, recheck_failed or snapshot_fresh); it has no `price_basis.stale_ack`; the row was never attempted (`!row._tries`; queue rows use UNDERSCORED fields `_tries _nextAt _parked _status`, till.html ~4331-4348, so the hold field is `_price_hold`; `_parked` means refused-for-good and is NOT reused). A network-failed first attempt must not bump `_tries` before the gate has run (case 12); the line is not an override (`price_basis.kept`, `money_override`, `credit_override` cover it).
At drain start (net up, key good, store not frozen): ONE recheck call (noQueue, chunks of 200 ids, the route cap) for the union of candidate item_ids.
A LINE is stale when ALL hold:
 a. the answer's `changed_at` (= commercial_changed_at; NEW additive field on recheckAnswer, api twin) is <= the bill's `billed_at` (sold after the change: the shop already had it, the till had not heard). A change AFTER billed_at is correct and silent (CTR-212 plan section 3, S3 rule).
 b. `changed_at` > `price_basis.snapshot_at` (the till's catalogue is older than the change; stamp compared to the snapshot, never to the wall clock).
 c. the line's sold `price` (minor) or `gst_rate` differs from the answer's `price` / `gst_rate`, or the answer says not sold (retired / redundant / inactive). Equal figures with a moved stamp (rename, re-save) = NOT stale, silent.
Deleted product (found:false) has no stamp and cannot be decided: the bill goes as sold, no popup (S3 files the ticket). Door error or timeout: see "Door down" in section 1b (the bill waits on the ladder and goes with the mark "Prices not checked" at its ceiling; v1 of this design sent it at once).
The line's `catalogue_stamp` is only a hint (R2) and is not used for the decision. The SERVER compares nothing in this slice. The server twin of the same test is CTR-212 S3 (drift ticket): it must treat `price_basis.stale_ack` as "already confirmed, no ticket" (note for that item).

## 1b. Edge rules (critic item 4; each has a test)
- ONE stamp = the LATEST change, no history. Stated false negatives, written as tests that expect SILENCE so the gap is named: (i) 09:00 100->120, bill 10:00 at 100, 10:30 120->125 (changed_at 10:30 > billed_at: missed); (ii) a change then a revert AFTER the bill. If exactness is wanted later, catalogue_item_version.valid_from has per-version history (ask cb-catalogue); not in this slice.
- Change then revert BEFORE the bill (09:00 to 120, 09:30 back to 100, bill 10:00 at 100): stamp 09:30, figures equal: silent, correct.
- Clock skew: billed_at is the TILL clock; changed_at and snapshot_at are SERVER clocks. The till already holds an offset (server `at` of the snapshot/recheck against the local receipt time): billed_at is converted to server time with it before rule a. Residual error is accepted in the false-popup direction only, never the miss direction; the words stay neutral ("the shop price is now 120.00"), never "sold wrongly". Test a till 2 h fast and 2 h slow.
- null `changed_at` (column absent because b845 is not run on production, or an older api sends no such key): a plain row = silent plus ONE toast per reconnect, "Price changes could not be checked yet." (silence is the bug). An adopted / inherited-rate line or a network `src:` item has no row stamp: values-only (rule c), no toast for those. A new till against an api without `changed_at` gets undefined and acts as the null case.
- Rate truth: DEFERRED to CTR-251 (review of 13 Nov). The gate reads "the rate moved" from the catalogue's resolved rate (recheckRateOf, today's context) plus the change stamp; it does NOT read the law pack's dated band at billed_at, so a catalogue edit made ahead of a law that takes effect later can hold a good bill (popup direction only, the owner PIN lets it go). Reading the band is cb-accounting's call with the credit-note remedy (CTR-251); it is not built here and not claimed.
- Soft-removed after the sale: removing a product stamps nothing (b845 excludes is_active), so nothing can say it happened before the sale; a soft-removed product NEVER holds a bill (tested, case 27). A retired STATUS moves the stamp and is held as not_sold.
- Door down (Athi, DECISIONS 0b876ee1): a bill that could not be checked stays queued on the retry ladder (_stale_tries, _nextAt), the next drain asks the door again, and at the ladder's ceiling (9th failed check) it goes with the mark "Prices not checked" (price_basis.stale_unchecked). Fail-open (the bill goes at once with the mark) is the same code behind STALE_DOOR_MODE = 'open', off until Athi turns it on. The gate runs before the first send, so a failed send can only follow a check or the mark.
- A bill whose row cannot be read is HELD with the reason (unreadable), never thrown at the queue; the gate itself failing sends every open bill as sold with one toast.
- S3 and this confirm never both fire for one bill: stale_ack (or a hold) is S3's skip key; one line is added in S3.

## 2. The confirm (money promise: a deliberate popup naming its reach; ui id `till-stale-send-popup`, path till.html > drain > staleSendAsk, with register id)
ONE grouped popup per reconnect (20 queued bills must not mean 20 popups), a row per bill.
Title: "Send these bills as they were sold?"
Per bill: "Bill 1042, 10:12, 236.00 paid". Per stale line: "Rice 5 kg: sold at 100.00, the shop price is now 120.00 (changed 09:00)". Rate move: "tax was 18%, now 12%". Not sold: "no longer sold".
Reach line, always: "The customer holds this bill at 236.00. Sending records it at 236.00 in the books and stock. It will not be re-priced. Until it is sent it is not in your books or stock. Not yet is only a delay: a bill the customer holds cannot be refused."
NO total and NO "would be" (critic item 1): re-totalling a finalised bill is a second calculation and needs a cart a queued bill does not have. The popup shows ONLY the carried values per line (sold price and rate; current price and rate from the recheck answer). The 283.20 / 224.00 figures live in the tests only as the hand oracle.
Buttons, both always shown: "Send as sold" (not the default focus; Enter does nothing, two deliberate taps) and "Not yet". Esc = "Not yet". NEVER opened mid-sale: while the cart is non-empty, a payment or PIN dialog is open, or the till is idle-locked, only the chip / banner shows; the popup opens at the next idle moment or on a chip tap.

### OPEN DECISIONS (Athi / cb-accounting). Marked OPTIONS; neither is built until answered.
(a) PRICE-ONLY move. Option A1 (critic's recommendation): send and record stale_ack with via 'auto', show the chip "Sent at an old price", feed S3's ticket; popup and hold only for a rate move or no-longer-sold. Option A2 (this document as written): confirm and hold for every stale line. A1 reason: a price-only confirm asks nothing the shopkeeper can act on and blocks day close. A1 deletes the popup for price-only lines and keeps everything else.
(b) RATE move. Option B1: owner PIN gates the send (as written below). Option B2: send as sold with reason 'rate_moved' and a credit-note remedy named in the chip (in India the rate at the time of supply governs; the PIN gates sending, not correctness). cb-accounting + Athi choose; if no gate, the PIN is dropped. stale_ack carries reason 'rate_moved' | 'price_moved' | 'not_sold' either way. When N>1 also "Send all N as sold" with the total sold (money unit M36, currency carried).
Who may press: price-only moves = any signed-in cashier (the sale already happened; refusing only holds money). A RATE move or a not-sold line = owner PIN (ownerPinAsk), because the tax invoice stands at a rate the pack no longer gives. Words: "Tax was 18% and is now 12%. The owner must say to send it." cb-accounting confirms this gate when the critic runs; if they say no gate, drop it.

## 3. The chip
Every held or stale bill carries a chip on the Bills list, the queue / stuck list and the bill detail: "Price changed: not sent" (amber, warnrow style; red stays for the server's own stop, CTR-191). Tap = reopen the popup for that one bill. After "Send as sold" the stored bill shows "Sent as sold: price had changed". Chip has a register id + path. The status-bar waiting count includes held bills with the words "waiting for your yes".

## 4. What "Send as sold" records (additive; figures untouched)
`business_json.price_basis.stale_ack = { at, by (tillStamp identity), by_name, via:'send_as_sold', reason:'price_moved'|'rate_moved'|'not_sold', owner_pin:bool, lines:[{ item_id, sold:{price, gst_rate}, current:{price, gst_rate, status}, changed_at }] }` plus `price_basis.stale_checked_at`. New keys need FIELDS.md entries (price_basis.stale_ack; recheck item `changed_at`). One shape per slot: they live in the existing price_basis slot, no new column, no migration. Money columns, line figures, totals, invoice and bridge are NOT changed (principle 0). The row is RE-READ by key before each put (a put of an older row object must never overwrite a hold or an ack; refusedRow races this) and written (DB.put) BEFORE the first send attempt so the idempotency key (hash of the body) is stable from then on; a row that has ever been tried is never re-asked.

## 5. If the owner says no ("Not yet")
Nothing is sent, deleted or re-priced. The queue row gets `_price_hold = { at, lines }`, persisted first so a reload or crash shows the chip. drain() skips it like a not-due row and says so (held count + words, never silent); other bills go on. It is asked again only on a tap on the chip, at day close (the close names it: "1 bill is waiting for a price decision"; close is refused with that sentence like any unsent bill, never auto-sent), and when an owner next signs in. No timeout, no hidden send. Exit: "Send as sold" ONLY. A credit note against a held, unsent bill waits behind it (WAITS_FOR_BILL), so a credit-note exit is not proven; until case 23 shows it, the chip says Send as sold is the only way and no cancel path is offered. Day close, wipeDevice and clear-store guards already refuse while queueCount()>0; `_price_hold` rows must count (STATE.queued = rows.length already counts them: test that queueCount() does not double count, 1 held bill = 1) (grep every DB.all('queue') length reader, the till-park lesson).

## 6. Offline queue safety (a bill is never lost)
- ORDER (critic blocker): drain marks candidates held (re-read the row, DB.put `_price_hold`) FIRST, sends every other bill, releases `_busy`, and only THEN a separate function raises the popup. The popup is NEVER awaited inside the send loop (an unanswered popup would hold every other bill behind it).
- Every sender passes the same gate: drain, drainSoon, sendNow, refresh / key-change drains (till.html ~5480-5540), "send this bill" in the bill list. sendNow on a held row sends nothing; qReady() (clears `_nextAt` only) never clears a hold.
- The gate lives ONLY in drain's pre-send step; finish(), the draft and the queue writes are untouched. Offline still never blocks a sale (TILL-41).
- A row is deleted only on server ack (unchanged). Hold, ack and popup answer are DB.put on the same row; if the put fails the bill is simply not sent this pass, with words. A frozen store REJECTS (till-park rule), never answers empty.
- Unattended reconnect (nobody at the till): candidates are held, everything else sends; nothing waits on a popup; the chip is there when someone returns.
- The recheck call runs `noQueue`, so the check itself can never enter the queue.
- Old-build bills (no price_basis) and checked:true bills pass untouched (counted, not asked).
- Replay safety: same body, same idempotency key; a second tap is harmless (row already put, the server replays).
- Shop scope: candidates are read through DB.all (foreign rows dropped); the shop key is re-checked at send (existing last gate).
- Guard test (till-park style): parse till.html; every awaited DB read added here is sorted gated / checked / closed in the table.

## 8. Hand-computed cases (engine path from the CTR-212 plan: 100.00 + 18% = 118.00 a unit; minor = x100; half-up to 2 places; intra-state heads split equally)
1. Core. Snapshot 08:00, Rice 100.00 at 18%. 09:00 owner raises Rice to 120.00 (changed_at 09:00). Till offline since 08:30. 10:00 bill qty 2: 200.00 + 36.00 = 236.00 (23600 minor), price_basis offline, snapshot_at 08:00. 11:00 reconnect: answer price 12000, changed_at 09:00. 09:00<=10:00, 09:00>08:00, 10000 != 12000 -> STALE. Popup names Rice 5 kg, 100.00 -> 120.00, paid 236.00 (popup shows carried values only; 283.20 = 240.00 + 43.20, 28320 minor, is the hand oracle for S2a, never shown). Send as sold -> posted total 23600, stale_ack.lines[0] sold.price 10000, current.price 12000; row deleted on ack. Break test: remove the gate -> posted silently, case fails.
2. Change after the bill: changed_at 10:30 (bill 10:00) -> rule a fails -> silent, sent 23600, no ack key.
3. Change before the snapshot: changed_at 07:30 (snapshot 08:00): the till already sold at 120.00 (240.00 + 43.20 = 283.20); prices equal -> silent. 3b (proves rule b ALONE): an adopted/kept line sold at 100.00 with changed_at 07:30 before the snapshot 08:00 and current price 120.00 -> silent.
4. Equal figures, stamp moved (rename at 09:00, price still 100.00): rule c fails -> silent.
5. Rate 18% -> 12% at 09:00, price 100.00: bill 236.00, today 200.00 + 24.00 = 224.00 (22400). Popup says tax 18% -> 12%; owner PIN needed; wrong PIN -> not sent, hold kept; right PIN -> sent at 23600, ack owner_pin true.
6. Tax-inclusive, qty 1, 100.00 incl 18%, intra: each head round(100 x 9/118) = 7.63, tax 15.26, taxable 84.74, total 100.00 (10000). Raised to 120.00 incl: each head round(120 x 9/118) = round(9.1525) = 9.15, tax 18.30, taxable 101.70, total 120.00 (12000). Popup: sold 100.00, shop price now 120.00 (no total); posted 10000 with taxable 84.74.
7. Retired product (status retired at 09:00): "no longer sold", owner PIN, sent as sold. Deleted (found:false): no popup, sent as sold, no ack.
8. Override line (kept at 100.00 by owner PIN earlier, price_basis.kept present): never stale, silent.
9. Two bills, one item (A qty 2 = 236.00, B qty 1 = 118.00, both stale): ONE popup, two rows, "Send all 2 as sold" with total 354.00 (35400); each bill's ack lists its own lines.
10. "Not yet" on case 1: server saw 0 requests, queue count stays 1, row has price_hold, reload keeps the chip, day close refuses with "1 bill is waiting for a price decision", wipeDevice refuses; later tap chip -> Send as sold -> 23600 posted.
11. Door 500 on reconnect: both bills posted as sold, one toast, no hold; the recheck call did not enter the queue.
12. A row with tries>0 and no ack is not asked (sent as is); a repeat send after ack replays by idempotency key, one chit.
13. Frozen store (blocked deleteDatabase): the gate rejects, nothing sent, banner shown (till-park guard).
14. Old-build bill with no price_basis, and a checked:true bill (online finish): pass untouched, counted.
15. Copy and UX: every sentence passes the copy lint; both buttons present in every state (a refused one greyed with its sentence); keyboard-only pass (Tab order, Esc = Not yet); 1366x768 and 390x844 no scroll.

### Cases added after the critic (16-25; "would be" removed from every popup test)
16. Later change hides an earlier stale: 09:00 100->120, bill 10:00 at 100, 10:30 120->125 -> silent (named false negative); same for a change then revert after the bill.

21. Drain with an unanswered popup: 20 bills queued, 1 held; the other 19 are posted, the held one stays, queueCount() = 1, _busy released.
