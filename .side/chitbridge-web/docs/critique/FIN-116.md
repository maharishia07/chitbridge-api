# FIN-116 PLAN (money): an in-app bank charge for a GST-registered AU shop carries GST (14 Nov 2026, finance) — critic BEFORE code
**Problem (walk W5/W15, I3).** In-app, a bank fee (22.00) is posted Dr 6090 22.00 / Cr 1500 22.00: no GST split, BAS credit lost. Cause: cap-bank.js bankAdd (:996) opens ＋ Entry with kind expense and never passes a tax kind; the engine's own rule is "a fee is not taxable or input-taxed by its name; the tax kind is ONLY the one the person taught" (engines src/bank-entry.js:27-29 kindNameOf_, src/reg-au.js:841 comment, auditor to confirm). So the fix is an ASKED fact, not a default.
**Existing path reused (no new calculation, no engine change).** (1) the owner picks a supply kind from the pack (CBRegulation.resolve(country).tax.supplyKinds, as bank-demo.js chartOf :207 does); (2) bank-preview.js resolveLine(key,{account,tax_kind}) → CBBankEntry.resolve (bank-entry.js:184) → recon.learn + recon.suggest → bank-entry.withTax (:51): the ONE splitter CBTax.splitLineTax splits the tax-inclusive statement figure (22.00 at 10% → GST 2.00, expense 20.00, amount + tax = the bank figure exactly); posting.post composes the lines; (3) CBBankPost (cap-bank-post.js) sends it as POST /events (event.input_tax) with client_ref = bank:<fingerprint>, series MJ (replay-safe).
**Which figure / which ledger.** For 22.00 at GST 10%: Dr 6090 Bank and merchant fees 20.00, Dr the pack's input-tax (GST paid) account 2.00, Cr 1500 Bank 22.00. The page computes nothing: the engine's tax record (kind, rate, tax_minor, credit, basis) is painted on the row (bank-demo lineNote/taxWordsOf :126-150 lifted).
**The ask.** New hold in bank-preview.js: only when the host passes opts.taxRegistered === true AND the proposal is an expense AND carries no tax record, the line is held with need `tax_kind` ("Tax needed": Does this carry GST? pick the kind: the pack's own supply-kind names), cleared by resolveLine with the proposal's own class + the chosen kind. The demo passes no taxRegistered, so its pass test (6 entries, books 13,428.50) cannot move.
**Refusal cases (all in words, none posts).** registration false OR unknown (null; SET-49: unknown is not false) → no GST question, nothing claimed, nothing defaulted, the row says "GST registration is not set, so no GST is claimed" ; pack with ≠1 tax head → withTax returns tax:null → the kind control is not offered and the row says why; unknown kind id → engine refuses (resolve ok:false), shown on the line; input-taxed/GST-free kind (rate 0) → entry whole, no split, recorded as the owner's answer; a credit above the pack's tax-invoice threshold → existing blocker tax_invoice (B5-03) asks; GST basis (cash/accrual) → existing blocker gst_basis asks once; closed month → lockedMonth refusal; not the owner → CBBankPost.ownerRefusal; same line twice → client_ref replay answers the first entry.
**Teaching.** resolve() makes one taught rule (device, source shown): the next fee like it carries the same kind, still a proposal.
**Landing.** web only (cap-bank-sheet.js new, bank-preview.js hold, bank-preview-ui.js lifted painter) + a web test (red before on origin shape: the in-app sheet posts without input_tax); no api change (POST /events already takes input_tax); no migration.
**Risks.** (a) bank-preview.js is shared with the demo: the hold is opt-in. (b) the rule key `bank_charges` class for resolve must be the proposal's own class (item.event.class), never a literal. (c) registration read = GET country-setup (tax.registered) once per sheet open; a failed read = unknown = no GST asked, said in words.
**Verdict (author, to be overruled by the critic):** BUILD AS PLANNED.
