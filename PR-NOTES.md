# fix/tax-lock-1128 (lane fixF4) — plan, written before the code (critic)
1. Amendment path in the code today: NONE. gst/close is idempotent (a second close answers duplicate); returns are reads of posted books. Reuse = the one period writer `books.setPeriod` + the one route `POST /periods/:fy/:p/unlock` (also reached by books-action postPeriod). No second lock path.
2. ONE definition "this month is inside a closed tax period": the return's own record (books-period.returnStateFor: set-off entry gstclose:<key> OR months a close locked). NOT only the reason prefix (a year close overwrites it).
3. setPeriod(..., reason, opts): opening such a month is refused in words ("reopen the tax close to amend it") unless opts.amendTax. The route takes `amend_tax: true` + reason; logged as "Tax close amended — <reason>". The maker-checker unlock has no flag, so it is refused.
4. Effect of an amend: the month opens, the period reads OPEN again (months not all locked) only if it had no set-off entry; with an entry it stays "set_off". Year close still names return_open for a period with no entry. NO new "amended return version" is built: that is a feature, listed as left over.
5. reopenYear keeps the lock: after the months go back to open, the months of every tax period closed by a set-off entry are re-stamped soft_locked with the 'Tax period closed — <label>' prefix (books-period-lock.relockClosed, same CLOSE_LOCK_REASON). Limit: a close with NOTHING to set off leaves no entry and the year close overwrote its prefix, so it is not restored (said in the report).
6. F3: yearState adds refusal `depreciation_not_run` (a stopping one, in BOOKS_REFUSALS) when the register holds an asset in the FY with value left and no 'depreciation:<fy>' entry. No register / no assets = no refusal. Law-neutral, same for IN/AU/AE.
7. Changes an existing decision? "unlock of a tax-closed month needs only a reason" (DECISIONS 30 Oct: the LOCK stays allowed) is about locking; unlock-with-reason stays, now with an explicit amend flag. reopenYear "posting opens" now holds only for months no tax close covers: this is the ordered F4 fix, flagged for the coordinator.
